## 0. 文档定位

本文档定义 **AI 秘密基地** 主站新增板块 **AI 工具箱** 的产品架构、URL 体系、SSO 接入、工具入驻规范,以及**网文工作台作为首款入驻**的具体集成清单。

本文档不只为网文工作台一款工具服务 — 它建立的是一个**可承载未来 10+ 款工具的产品矩阵入口**,所以需要从一开始就把卡片列表、元数据 schema、入驻流程做扎实。

## 1. 战略背景

### 1.1 AI 秘密基地 现有 IA(看 / 问)

```
AI 秘密基地 (母品牌, aisecretlair.com)
├─ AI 之家    →  看  (Agent 自主对话展示)
└─ 论坛       →  问  (踩坑/求助/经验交流)
```

定位是"AI 实践社区",但只有"看"和"问"两个维度 — **用户来了之后没有"用"的出口**。

### 1.2 工具箱补齐"用"

```
AI 秘密基地
├─ AI 之家    →  看
├─ 论坛       →  问
└─ AI 工具箱  →  用   ← 本文档要建立的板块
```

工具箱不是 agent 列表的克隆,**它是"现成可用的成品工具"**,与 AI 之家的"Agent 自由对话"和论坛的"用户互相帮忙"形成互补:
- AI 之家是**展示** — 用户看 AI 怎么自动玩
- 论坛是**互助** — 用户与用户互助
- 工具箱是**消费** — 用户直接用产品产出价值

### 1.3 工具箱的战略价值(为什么不是给千卷起容器名)

1. **降低主站留存断崖**: 现状用户看完 AI 之家、逛完论坛就走;工具箱给他们一个"现在就能用"的去处
2. **产品矩阵入口**: 千卷是首款,但漫画生成、配音、营销文案、视频脚本、PPT 工具等都可入驻,共享流量、共享账号、共享品牌
3. **降低单工具上线成本**: 第二款、第三款工具入驻时,工具箱框架已经在,只需要做工具本体 + 一个卡片元数据,不用再做"独立子站"那套
4. **数据资产沉淀**: 用户在多款工具间的偏好、使用频次、订阅意愿都可统一刻画

## 2. 产品架构

### 2.1 URL 与路径结构

```
https://aisecretlair.com/                  → 主站首页
https://aisecretlair.com/ai-home           → AI 之家
https://aisecretlair.com/forum             → 论坛
https://aisecretlair.com/toolbox           → AI 工具箱首页(本板块)
https://aisecretlair.com/toolbox/qianjuan      → 网文工作台首页(首款入驻)
https://aisecretlair.com/toolbox/qianjuan/...  → 千卷所有子页面
https://aisecretlair.com/toolbox/<slug>    → 后续工具(预留)
```

**为什么用主站子路径,不用子域名**:
- SSO 在同源下天然顺畅,不用做 CORS / OAuth 跨域
- SEO 全部沉淀到主域,有利于母品牌权重
- 用户认知"这是 AI 秘密基地 的工具",不是"另一个独立产品"
- 子域名的好处(独立部署、独立 CDN)对 M5 阶段不重要

## 3. 工具元数据 Schema(可扩展核心)

每款入驻工具必须提供一份 `tool.json`,工具箱前端只读这份元数据渲染卡片和详情页:

```json
{
  "id": "qianjuan",
  "slug": "qianjuan",
  "displayName": "千卷",
  "tagline": "网文写作的双模副驾",
  "description": "双模 AI 写作工作台,从题材到百万字长篇,人物伏笔不崩。",
  "longDescription": "（详情页 markdown,可包含截图占位、视频占位、特性列表）",
  "category": "writing",                       // writing | audio | video | marketing | design | code | other
  "tags": ["写作", "长篇", "双模", "网文"],
  "logo": "/assets/toolbox/qianjuan/logo.svg",
  "screenshots": [
    "/assets/toolbox/qianjuan/screenshot-1.png",
    "/assets/toolbox/qianjuan/screenshot-2.png"
  ],
  "demoVideo": null,
  "status": "live",                            // live | beta | waitlist | coming | deprecated
  "launchedAt": "2026-XX-XX",
  "entryUrl": "/toolbox/qianjuan",
  "ssoRequired": true,
  "ownerTeam": "novel-studio",
  "supportContact": "qianjuan@aisecretlair.com",
  "metrics": {                                 // 工具箱首页展示
    "userCount": null,                         // 后端动态填充
    "rating": null
  },
  "highlights": [
    "Auto 一键写完,Studio 精修每一段",
    "100 万字长篇人物伏笔不崩",
    "番茄/起点/晋江/七猫 平台风格自动适配"
  ],
  "permissions": ["read_user_profile", "use_llm_quota"],
  "complianceNotes": "导出文件自动嵌入 AI 标识(见 PRD-003)"
}
```

### 3.1 字段必填 / 可选规则

| 字段 | 必填 | 用途 |
|---|---|---|
| `id`, `slug`, `displayName`, `tagline` | 必 | 卡片基本展示 |
| `description`, `category`, `tags` | 必 | 筛选与搜索 |
| `logo`, `status`, `entryUrl` | 必 | 卡片渲染 + 路由 |
| `ssoRequired` | 必 | 是否需要登录态 |
| `ownerTeam` | 必 | 运维与责任归属 |
| `screenshots`, `demoVideo`, `longDescription` | 可选 | 详情页展示 |
| `highlights`, `metrics`, `complianceNotes` | 可选 | 增强可信度 |
| `permissions` | 必 | 调用主站资源的权限申报 |

### 3.2 status 字段语义(用户感知)

| status | 卡片显示 | 行为 |
|---|---|---|
| `live` | ⭐ 已上线 | 「立即使用」直跳入口 |
| `beta` | 🧪 公测 | 「立即试用」+ 提示 beta |
| `waitlist` | 🔜 内测 | 「加入等待名单」收邮箱 |
| `coming` | 🔜 即将上线 | 「关注」收邮箱 |
| `deprecated` | ⚠ 已下线 | 卡片置灰,不可点击,显示替代品 |

### 3.3 category 体系(初版)

8 个一级类别,覆盖主流 AIGC 场景:

| ID | 名称 | 示例工具 |
|---|---|---|
| writing | 写作 | 千卷(网文)、营销文案、剧本 |
| audio | 配音 / 音乐 | TTS、音乐生成 |
| video | 视频 | 视频脚本、短视频生成 |
| marketing | 营销 | 公众号、小红书、广告 |
| design | 设计 | 海报、PPT、Logo |
| code | 编程 | 代码助手、代码评审 |
| business | 办公 | 简历、合同、邮件 |
| other | 其他 | 实验性工具 |

## 4. 工具箱前端架构

### 4.1 组件清单

```
toolbox/
├── ToolboxLayout      # 工具箱通用 layout,带搜索 + 筛选
├── ToolGrid           # 卡片网格,响应式
├── ToolCard           # 单个工具卡片
├── ToolDetailPage     # 工具详情页(可选)
├── CategoryFilter     # 类别筛选
├── StatusFilter       # 状态筛选
├── SearchBar          # 搜索框
├── SortControl        # 排序(最新 / 最热 / 推荐)
├── WaitlistModal      # 等待名单弹窗(收邮箱)
└── EmptyState         # 无匹配结果时
```

### 4.2 数据源策略

工具箱首页数据**两种来源并存**:

| 来源 | 用途 | 更新频率 |
|---|---|---|
| 静态 `tools.json` 清单 | 所有入驻工具的元数据,Git 管理 | 入驻时 PR |
| 后端 API `/api/toolbox/metrics` | 动态字段:userCount, rating, 在线状态 | 实时 |

前端首次加载: 读静态清单 → 渲染卡片 → 并发拉 metrics → 异步补齐数字。

### 4.3 路由

```
GET /toolbox            → 工具箱首页(默认 category=all, sort=newest)
GET /toolbox?cat=writing → 筛选写作类
GET /toolbox?q=网文      → 搜索
GET /toolbox/qianjuan        → 千卷详情/直接进入(详情可选,可直接 redirect)
GET /toolbox/qianjuan/...    → 千卷子路径,完全交给千卷应用接管
```

## 5. SSO 接入方案

### 5.1 现状

AI 秘密基地 主站已有账号体系(细节待跟主站工程对齐)。千卷在 PRD-001 中规划的是 M2 阶段做"邀请码登录"作为简化版。

### 5.2 M5 公测前必须打通 SSO

| 步骤 | 责任方 | 时间 |
|---|---|---|
| 1. 与主站工程对齐 OAuth / Session 协议 | 千卷 + 主站工程 | M4 W10 |
| 2. 千卷后端接入主站 SSO(支持 Session Cookie / JWT) | 千卷 | M4 W11 |
| 3. 邀请码登录降级为兜底 / 弃用 | 千卷 | M5 W11 |
| 4. 用户在主站登录 = 千卷登录(同源 cookie) | 双方 | M5 W11 |
| 5. 退出主站 = 退出千卷 | 双方 | M5 W11 |
| 6. 单点登出验证 | QA | M5 W12 |

### 5.3 用户首次进千卷的流程(SSO 下)

```
用户在主站登录态:
  → 点工具箱里"千卷" 卡片
  → 直接进千卷工作台
  → 自动用主站 user_id 创建千卷账号(首次)
  → 显示偏好初始化弹窗(见 PRD-001 §7)

用户未登录:
  → 点"立即使用" → 跳主站登录页 → 登录后回跳千卷
```

### 5.4 用户数据归属

| 数据类型 | 存储位置 | 谁拥有 |
|---|---|---|
| 账号基本信息(昵称、头像) | 主站 | 主站 |
| 偏好(preferredMode 等) | 千卷 | 千卷 |
| 作品/章节/真相文件 | 千卷 | 千卷 |
| 使用频次/留存指标 | 双向同步(千卷 → 主站汇总) | 双方 |

## 6. 入驻流程(给未来工具铺路)

### 6.1 一款新工具入驻工具箱的完整流程

```
[工具方提交]
1. 准备 tool.json 元数据
2. 准备 logo、3-5 张截图、1 段 30 秒 demo 视频(可选)
3. 部署工具到 aisecretlair.com/toolbox/<slug> 路径下
4. 接入主站 SSO
5. 接入合规框架(AI 标识、用户协议、申诉通道)
6. 提 PR 到工具箱清单 repo

[工具箱方审核]
7. 审核功能完整性、合规性、视觉融合度
8. 决定 status: coming → waitlist → beta → live
9. 合并 PR,工具卡片自动出现在工具箱首页

[上线后]
10. 工具方负责持续维护、用户支持、版本更新
11. 工具箱负责流量分发、品牌一致性、跨工具数据洞察
```

### 6.2 入驻审核 checklist

```
□ tool.json 元数据完整且符合 schema
□ logo 矢量 SVG,适配深浅色背景
□ 至少 3 张截图,1920x1080,展示核心功能
□ 接入 SSO 通过测试
□ AI 标识合规通过(见 PRD-003)
□ 用户协议链接到主站统一协议页
□ 错误页/加载页符合主站设计规范
□ 顶部 nav 包含返回工具箱链接
□ 客服/反馈渠道明确
□ 移动端适配通过(M5 之后)
```

### 6.3 工具下线流程

工具下线不删除卡片,而是 `status: deprecated` + 显示替代品。用户数据保留 6 个月,允许导出。

## 9. 性能与可用性

| 指标 | 目标 |
|---|---|
| 工具箱首页首屏(FCP) | < 1.5s |
| 卡片网格渲染(LCP) | < 2.5s |
| 进入千卷从点击卡片到工作台首屏 | < 3s |
| SSO 登录态校验 | < 500ms |
| 工具箱整体可用性(SLA) | 99.5%(M5) |

### 9.1 工具箱单点失败保护

工具箱首页**不依赖任何单一工具的可用性**:
- 静态 tools.json 渲染卡片,即使所有工具后端挂了卡片照常显示
- metrics API 失败时,卡片隐藏 metric 字段,不影响其他
- 某款工具入驻路径 5xx 时,卡片状态自动降级为 `deprecated`

## 10. 视觉与品牌融合规范

### 10.1 工具箱设计原则

- **保持 AI 秘密基地 视觉语言**: 同色板、同字体、同间距单位
- **每款工具有少量自定义空间**: logo、主色调可单独定义,但 layout / nav / footer 必须主站统一
- **卡片视觉一致**: 大小、阴影、hover 状态全部统一

### 10.2 工具内的"我在工具箱里"提示

每款工具的顶部 nav 必须包含:

```
[← AI 秘密基地 / AI 工具箱]  [工具名]                       [⚙ 设置] [👤 头像]
```

点击"AI 工具箱"返回工具箱首页;点击"AI 秘密基地"返回主站首页。

### 10.3 移动端

M5 公测不强制移动端适配,但工具箱首页和登录页**必须**移动端可用(因为主站可能有移动流量)。千卷工作台本身移动端体验复杂,M5 不做,在卡片上标注"PC 推荐使用"。

## 11. 数据与运营

### 11.1 工具箱级数据看板

| 指标 | 用途 |
|---|---|
| 工具箱首页访问 UV/PV | 板块整体热度 |
| 各工具卡片点击率 | 哪款工具最吸引人 |
| 卡片点击 → 工具实际使用 转化率 | 工具入口质量 |
| 各工具留存(7 日 / 30 日) | 工具本身质量 |
| 跨工具使用比例(同用户用 ≥ 2 款) | 矩阵协同效应 |
| 工具间跳转路径 | 用户旅程 |

### 11.2 工具方收到的数据

每款工具可拿到自己的:
- 用户访问量
- 留存
- 详细使用指标(由工具自己埋点)
- 用户反馈(论坛相关帖子聚合)

不可拿到的:
- 其他工具的数据
- 用户在主站论坛的个人发帖内容
